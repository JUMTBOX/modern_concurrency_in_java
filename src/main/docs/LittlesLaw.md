### 가상 스레드 확장성의 근본 원칙(리틀의 법칙)
- 리틀의 법칙은 멀티스레드 애플리케이션을 포함한 `큐잉(queueing)` 시스템의 성능에 대해 귀중한 통찰력을 제공하는 근본 원칙이다.
- 이 법칙은 모든 컴퓨팅 시스템의 성능과 본질적으로 연결된 세 가지 핵심 요소인 <br/>
  `시간(latency)`,`동시성(concurrency)`,`처리량(throughput)` 사이에 수학적 관계를 설정한다.
- 안정적인 시스템에서 처리량은 다음 공식으로 주어진다고 설명한다.
```text
T = N/d
```
- `처리량(throughput): T`
  - 단위 시간당 완료되는 항목(예: 태스크, 요청)의 평균 수
- `동시성(concurrency): N`
  - 동시에 처리되고 있는 항목의 평균 수
- `응답 시간(latency): d`
  - 단일 항목이 시작되고 완료까지 처리되는 데 걸리는 평균 시간

```text
리틀의 법칙이 놀라운 점은 설명하는 시스템의 성격에 구애받지 않는다는 것이다.
이 법칙은 '작업 수행'에 걸린 시간과 '대기'에 걸린 시간을 구분하지 않으며, 동시성 단위가 스레드인지,
CPU코어인지, ATM 기계인지, 심지어 인간 은행원인지도 신경 쓰지 않는다.
이 법칙은 그저 처리량을 늘리기 위한 공식을 제공할 뿐이다.
```
**가상 스레드와 리틀의 법칙**
- 전통적인 스레드 모델링은 종종 생성할 수 있는 스레드 수에 대한 운영체제 수준의 제약 때문에 한계에 부딪힌다.
- 이러한 상황에서 시스템의 처리량은 리틀의 법칙에 의해 제한된다.
- `이 법칙은 우리가 N(동시성)을 늘릴 수 없다면, 조작할 수 있는 변수는 단 하나, d(지연 시간)만 남는다는 것을 보여준다.`
- 하지만 문제는 I/O 집중적인 작업에서 지연 시간을 줄이는 것이 `항상 개발자의 통제 범위 내에 있지 않다는 것이다.`

```text
이 지점에서 가상 스레드가 등장한다. 가상 스레드를 사용하면 프로그래밍 모델을 변경할 필요 없이
훨씬 더 높은 N, 즉 높은 동시성을 확보할 수 있으므로 전통적인 스레딩 모델의 제약에서 벗어날 수 있다.
더 높은 N은 리틀의 법칙에서 확인할 수 있는 것처럼, 더 높은 처리량으로 직접 이어진다.
가상 스레드는 d를 줄이지 않고도 T를 늘릴 수 있는 비결이다.
```

```markdown
실제 운영 환경에서 더 엄격한 성능 분석을 하려면 다음의 개선 사항들을 고려하여야 한다.
 - JIT(just-in-time) 컴파일 효과를 반영하기 위한 JVM 워밍업 실행
 - 통계 분석(평균, 표준편차)을 포함한 여러 번의 벤치마크 반복 실행
 - 자원 트레이드오프를 이해하기 위한 메모리 사용량 모니터링
 - 실제 환경 조건을 모델링하기 위해 지연 시간 변동(+- 10 ~ 20%)을 적용한 현실적인 I/O 시뮬레이션
 - 견고한 측정을 위한 타임아웃 및 적절한 오류 처리

이러한 개선사항들은 실제 성능 차이와 측정상의 오류를 구분하는 데 도움을 주고, 이로부터 실제 운영 환경에서 <br/>
의사결정을 할 때 더 신뢰할 수 있는 통찰을 얻을 수 있다. <br/>
중요한 성능 평가는 `JMH(Java Microbenchmark Harness)`와 같이 이미 널리 사용되어 <br/>
안정적인 마이크로벤치마킹 프레임워크 사용을 고려하는 것이 좋다.
```

**`I/O bound 위주의 작업이 많고, CPU 집중적인 작업이 적은 경우 가상 스레드가 효과적으로 동작할 수 있다.`**
